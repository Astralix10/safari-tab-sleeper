# Safari Tab Sleeper 0.3.11 (build 29): аудит

Дата: 5 сентября 2026 года. Исходная версия: 0.3.10 (28).

## Обнаружено и исправлено

1. **P1: гонка при усыплении.** За время проверки страницы вкладка могла стать активной, закреплённой или защищённой. Теперь перед навигацией повторно проверяются адрес, состояние, текущие настройки и данные страницы. Массовая очистка также не затрагивает вкладку, выбранную во время операции.
2. **P1: потеря адреса восстановления.** Локальная страница открывалась раньше подтверждения записи архива. Теперь адрес сохраняется на диск до навигации. При ошибке вкладка остаётся открытой, подготовленные записи откатываются.
3. **P1: удаление используемых токенов.** Дедупликация и лимит архива удаляли записи открытых спящих вкладок. Теперь активные токены сохраняются, включая несколько вкладок с одним URL; лимит и дедупликация применяются к неиспользуемым записям. Состояние сохраняется после перезапуска сервера. Расширение также восстанавливает записи архива из собственного хранилища.
4. **P1: восстановление другой страницы.** Отложенная операция могла перезаписать вкладку после перехода на другой адрес. Восстановление теперь проверяет текущий токен или состояние native discard. Сообщение страницы использует tab ID отправителя.
5. **P2: неполное массовое пробуждение.** Вкладки, отсутствующие в extension storage, не попадали в список. Теперь команда перечисляет реальные вкладки и восстанавливает записи по токену из локального архива, включая дубликаты.
6. **P2: неверный отсчёт времени.** Таймер опирался на последнее сканирование активной вкладки. Теперь уход с вкладки записывает время деактивации; порог агрессивного режима остаётся пять минут.
7. **P2: устаревшее состояние медиа.** Кэшированный флаг воспроизведения мог навсегда блокировать сон после паузы. Перед решением выполняется свежая проверка. Также учитываются доступные вложенные фреймы и видео без звука; загружаемые и уже выгруженные страницы пропускаются.
8. **P2: потеря одновременных изменений защиты.** Два переключателя могли перезаписать allowlist друг друга. Изменения настроек сериализованы. Popup больше не выполняет независимую запись всего объекта настроек при ошибке worker. Правило с wildcard не может ложно показать выключенную защиту.
9. **P2: преждевременное пробуждение.** Watchdog мог сразу разбудить текущую вкладку, усыплённую вручную, и игнорировал настройку восстановления. Проверки исправлены.
10. **P2: ложные срабатывания проверки форм.** Служебные hidden-поля и исходное значение select могли считаться несохранённым вводом. Проверка исключает служебные контролы и учитывает начальный выбор select.
11. **P2: обход защиты через AppleScript.** Прямой HTTP endpoint ручного усыпления закрыт с ответом `extension-required`. Ручные действия проходят через те же проверки, что и автоматические.
12. **P2: разбор адресов на локальной странице.** Убрано извлечение HTTP-адресов из произвольного текста и JavaScript. Разрешены веб-адреса и известные Reader-обёртки.
13. **P2: конкурентные запросы к архиву.** При одновременных подключениях сервер мог сбрасывать соединения из-за маленькой очереди. Очередь увеличена; проверены 40 параллельных записей.
14. **P3: лишние записи и зависания интерфейса.** Синхронизация одинаковых настроек объединяется, неизменные данные не переписываются на диск, повторяющиеся сообщения страницы подавляются. Чтение ответа и запросы состояния страницы имеют таймауты. Убраны отдельные уведомления о количестве видео ниже порога памяти.
15. **P3: неверный статус host app.** Убрана гонка между ответом Safari и устаревшим heartbeat. Явное состояние Safari имеет приоритет. Устранены предупреждения Swift при сборке новым Xcode.
16. **P1: отказ 403 при чтении данных помощника.** В живом Safari запросы GET расширения приходят без Origin. Сервер отклонял чтение памяти, питания и команд очистки, хотя heartbeat работал. Общий заголовок клиента теперь сопровождает секретный токен. В инспекторе проверено: прежний запрос получает 403, исправленный 200. Запрос обычного сайта даже с заголовками клиента отклоняется отдельным регрессионным тестом.

## Проверка

- 95 автоматических тестов: core, фоновые события Safari в изолированном API, HTTP API, архив, параллельные записи, локальная страница, memory guard и UI-контракты. Все проходят.
- Тесты worker выполняют настоящий модуль, отправляют события и проверяют совершённые навигации и записи. Дополнительно сохранены прежние проверки ресурсов.
- Компиляция AppleScript, синтаксис shell/Python и Release-сборка Xcode с проверкой подписи.
- Два полных перезапуска Safari: расширение остаётся включённым, heartbeat сообщает 0.3.11; в панели отображаются память и питание. PluginKit показывает одну установленную копию.
- Полный пятиминутный цикл и клики переключателя в Safari пока не подтверждены: интерактивная проверка прерывалась переключением и закрытием тестовых вкладок. Автотесты этих сценариев не заменяют такую end-to-end проверку.
- Исходники восстановлены в отдельный checkout из GitHub: прежняя рабочая папка содержала неполный `.git` и не содержала JavaScript-файлов. Код восстановленной версии совпал с установленной 0.3.10; оставшиеся локальные файлы не перезаписывались.

## Ограничения

- Пятиминутный порог проверяется минутным alarm. Во время сна Mac и задержек планировщика Safari выполнение может произойти позже.
- В Safari используется лёгкая страница сна, если native discard недоступен. Полная копия поведения Chrome не обещается.
- Показатель памяти относится к процессам Safari/WebKit, а swap является общесистемным. Точную память отдельной вкладки публичные API не предоставляют.
- Недоступные для проверки страницы пропускаются. Сложные редакторы, закрытые shadow roots, защищённые фреймы и нестандартные медиадвижки требуют отдельной проверки.
- Исправление архива предотвращает новые потери. Уже удалённую старой версией запись нельзя восстановить только по случайному токену, если её нет ни в одном хранилище.
